# 🎯 SRC 폴더 구조 가이드

## 📁 핵심 폴더 구조

```
src/
├── 📂 application/            → 애플리케이션 계층 (Use Cases, 비즈니스 로직 조율)
│   └── 비즈니스 유스케이스 구현 및 도메인 서비스 조율을 담당하는 애플리케이션 서비스
│
├── 📂 domain/                 → 도메인 계층 (핵심 비즈니스 로직 및 엔티티)
│   └── 순수한 비즈니스 로직과 도메인 모델, 비즈니스 규칙을 정의하는 핵심 계층
│
├── 📂 infrastructure/         → 인프라 계층 (외부 시스템 연동 및 구현 세부사항)
│   └── Firebase, API, 외부 서비스와의 실제 통신 및 데이터 영속성 구현
│
├── 📂 components/             → 재사용 가능한 React UI 컴포넌트
│   └── 버튼, 폼, 모달 등 프로젝트 전반에서 재사용되는 UI 구성 요소
│
├── 📂 pages/                  → 라우팅 페이지 컴포넌트
│   └── 각 URL 경로에 매핑되는 최상위 페이지 컴포넌트 (예약관리, 객실관리 등)
│
├── 📂 services/               → 서비스 레이어 (API 통신 및 비즈니스 로직)
│   └── Firebase 연동, 데이터 처리, 외부 API 호출 등의 서비스 로직
│
├── 📂 hooks/                  → 커스텀 React Hooks
│   └── 재사용 가능한 상태 관리 및 사이드 이펙트 처리 로직
│
├── 📂 stores/                 → 전역 상태 관리 (Zustand)
│   └── 앱 전체에서 공유되는 상태 저장소 (사용자 정보, 앱 설정 등)
│
├── 📂 utils/                  → 유틸리티 함수
│   └── 날짜 포맷팅, 문자열 처리, 유효성 검사 등 공통 헬퍼 함수
│
├── 📂 constants/              → 상수 정의
│   └── API 엔드포인트, 에러 메시지, 설정값 등 불변 상수값
│
├── 📂 config/                 → 설정 파일
│   └── Firebase 설정, 환경별 설정, 앱 초기화 설정
│
├── 📂 styles/                 → 전역 스타일 및 테마
│   └── CSS 모듈, 전역 스타일시트, 테마 변수 정의
│
├── 📂 assets/                 → 정적 리소스
│   └── 이미지, 폰트, 아이콘 등 정적 파일 리소스
│
├── 📂 providers/              → Context Providers
│   └── React Context API를 사용한 전역 상태 및 테마 제공자
│
├── 📂 models/                 → 데이터 모델 정의
│   └── TypeScript 인터페이스, 데이터 구조 정의 (예약, 객실, 사용자 모델)
│
├── 📂 common/                 → 공통 모듈
│   └── 여러 계층에서 공유되는 공통 유틸리티 및 타입 정의
│
└── 📂 scripts/                → 빌드 및 유틸리티 스크립트
    └── 데이터 마이그레이션, 테스트 데이터 생성 등 개발 지원 스크립트

## 🎯 계층별 주요 책임

### Clean Architecture 계층
1. **domain/** - 비즈니스 규칙과 엔티티 (의존성 없음)
2. **application/** - 유스케이스 구현 (domain만 의존)
3. **infrastructure/** - 외부 시스템 연동 (모든 계층 의존 가능)

### UI/UX 계층
1. **pages/** - 라우팅 및 페이지 레이아웃
2. **components/** - 재사용 가능한 UI 요소
3. **hooks/** - 상태 및 로직 재사용

### 지원 계층
1. **services/** - API 및 외부 서비스 통신
2. **stores/** - 전역 상태 관리
3. **utils/** - 헬퍼 함수 및 유틸리티
